Qué es esta página

Revisa qué tan protegida está la información confidencial de una base de datos Oracle, siguiendo la norma ISO 27001. Identifica qué podría salir mal y qué medidas lo evitarían, mide con un diagnóstico ejecutado sobre la base real cuáles de esas medidas existen y termina con un plan de mejora para aplicar las que faltan.

Entorno: el enunciado propone Oracle 21c XE; este trabajo usa Oracle 26ai Free en Docker. Los términos técnicos se explican en el glosario.

Componente 1 · Planificar

      
Riesgos de confidencialidad R-CONF

      
Cinco escenarios en los que datos de la base Oracle pueden llegar a quien no debe verlos. Cada uno se valora con probabilidad e impacto de 1 a 5; el nivel es el producto P × I.

      
Exigido: al menos 5 riesgos R-CONF con impacto y probabilidad (§3 y §6.1). Propio: las escalas, porque el PDF no las define.

    

    
En palabras simples
Un riesgo es algo que podría hacer que un dato confidencial (un salario, una contraseña, un correo) lo vea quien no debe. Cada riesgo recibe una nota de probabilidad, qué tan fácil es que pase, y de impacto, qué tan grave sería, de 1 a 5. Multiplicadas dan su nivel: mientras más arriba y a la derecha en el cuadro, más urgente.

    

      

        

        
Impacto 1Impacto 5

      

      

        

          
PProbabilidad

          
            
1Rara: requiere varias fallas simultáneas

            
2Improbable: requiere un error poco común

            
3Posible: la condición existe en entornos típicos

            
4Probable: la condición existe por defecto o por práctica común

            
5Casi segura: ya ocurre o es trivial de explotar

          

        

          
IImpacto

          
            
1Insignificante: datos públicos

            
2Menor: datos internos sin datos personales

            
3Moderado: pocos registros personales

            
4Mayor: muchos registros personales o datos económicos

            
5Crítico: exposición masiva de datos personales (Ley 8968)

          

        
Nivel: Bajo 1-6 Medio 8-12 Alto 15-25

Componente 4 · Verificar

      
Quince controles observables por un auditor externo

En palabras simples
Un control observable es una comprobación que otra persona puede hacer sin creerle al administrador: ejecuta algo y mira el resultado. Si el resultado coincide con el criterio de aceptación, la medida existe.

Componente 5 · Verificar y actuar

      
Matriz de evaluación

      
Cada fila cruza una tarea, un riesgo y un control. El nivel actual es la línea base medida el 20 oct 2026; se vuelve a medir con la prueba PT indicada cuando el control esté implementado.

      
Exigido: columnas Tarea, Riesgo, Control, Criterio 0-4, Evidencia y Estado (Cumple / No cumple / Parcial) (§3 y §6.5). Propio: la definición de los niveles, porque el PDF no la da. La columna Evidencia cita el bloque del diagnóstico y la prueba PT que confirmará el nivel cuando se aplique la acción del plan de mejora.

    

    
En palabras simples
Es la tabla de notas. Cada fila combina una tarea, un riesgo y un control, y recibe un nivel de 0 a 4 según la evidencia: 0 y 1 significan No cumple, 2 es Parcial, y 3 y 4 son Cumple. Todas las filas están en 0 o 1 porque la base usa la configuración de fábrica; el plan de mejora indica qué hacer para subir cada una.

Batería de pruebas y scripts de verificación

      
Diecisiete pruebas para Oracle 26ai Free en Docker que comprueban cada control una vez aplicado. Forman la batería propuesta del plan de mejora; la prueba ejecutada en este trabajo es el diagnóstico de la línea base. Cada salida se guarda como evidencia EV con el mismo número que la prueba.

      
Exigido: ID, Tipo, Procedimiento, Resultado esperado y Herramienta (§6.6), scripts de verificación obligatorios (§6) y ejecución real (§3). Propio: las columnas Riesgo, Control y Evidencia, para trazabilidad.

    

    
En palabras simples
Cada prueba es un script que se ejecuta en la base para demostrar que una medida funciona; por ejemplo, intentar leer una tabla sin permiso y comprobar que Oracle lo impide. Están listas para ejecutarse a medida que se aplique cada acción del plan de mejora. Debajo del nombre de cada prueba se explica qué demuestra; el código está dentro, al abrirla.

    

      

        
Conexión

        
SQL Developer en Windows: usuario SYS como SYSDBA, host localhost, puerto 1521, servicio FREEPDB1. Para comandos que exigen la raíz (TDE, clonación), conéctate al servicio FREE o usa ALTER SESSION SET CONTAINER = CDB$ROOT.

        
Desde el contenedor: docker exec -it oracle-eliasulate sqlplus / as sysdba y luego ALTER SESSION SET CONTAINER = FREEPDB1;

Plan de mejora

      
Trece acciones, una por hallazgo, ordenadas por prioridad. Cada una indica qué filas de la matriz mejora y con qué prueba se comprueba; al aplicarla y pasar su prueba, esas filas pueden subir a nivel 3 (Cumple).

      
Exigido: metodología PHVA (§1 y §7); esta es la fase Actuar. Propio: el orden de prioridad, basado en la gravedad de cada hallazgo.

    

    
En palabras simples
Es la lista de correcciones para lo que encontró el diagnóstico. Primero van las que protegen más datos. Las pruebas de la batería sirven para demostrar que cada corrección quedó bien hecha.

Antes de aplicar cambios

        
Las pruebas PT usan un esquema de demostración, APP_OWNER, con datos ficticios, para no alterar los proyectos del curso que dependen de BASES1 y GESTOR_RMAN.

        
Los cambios sobre cuentas y tablas reales (quitar el rol DBA a BASES1, purgar la papelera, cerrar puertos) deben coordinarse con esas aplicaciones, porque pueden dejarlas sin acceso.

        
Antes de cualquier cambio, respaldar el volumen o exportar FREEPDB1.

      

      

        
Cómo medir el avance

        
El diagnóstico se repite con demostracion_diagnostico.ps1, que guarda cada corrida en una carpeta con fecha. Comparar la corrida nueva con la línea base muestra qué filas de la matriz subieron de nivel.

      

    

  


  

    

      
Referencia

      
Glosario

      
Los términos técnicos que aparecen en la página, explicados en una o dos líneas.

    

    

      
Confidencialidad
Que solo quien está autorizado pueda ver un dato.

      
DBA
Administrador de bases de datos: quien instala, configura, respalda y protege la base.

      
ISO/IEC 27001, Anexo A
Norma internacional de seguridad de la información. Su Anexo A lista 93 medidas (controles); el profesor eligió 15.

      
ISO/IEC 27002
Guía que explica cómo aplicar cada control de la ISO 27001.

      
Ley 8968
Ley costarricense de protección de datos personales. Obliga a guardar confidencialidad y a borrar datos cuando corresponde.

      
PHVA
Planificar, Hacer, Verificar, Actuar: el ciclo de mejora que sigue el proyecto.

      
CDB y PDB
Oracle guarda varias bases «enchufables» (PDB) dentro de un contenedor (CDB). FREEPDB1 es la base de trabajo; FREEPDB2 es otra base del mismo contenedor.

      
SYS y SYSDBA
La cuenta y el permiso con control total sobre Oracle.

      
Rol DBA
Paquete de permisos de administrador completo: quien lo tiene puede leer y cambiar casi todo.

      
Privilegio ANY
Permiso para actuar sobre objetos de cualquier usuario; por ejemplo, SELECT ANY TABLE permite leer cualquier tabla.

      
Grant
La acción de dar un permiso a un usuario o a un rol.

      
Perfil de contraseñas
Reglas de una cuenta: cuántos intentos fallidos se permiten, cada cuánto vence la contraseña, qué tan compleja debe ser.

      
Verificador 11G / 12C
Formato en que Oracle guarda la contraseña cifrada. El 11G es antiguo y más débil que el 12C.

      
TDE (cifrado transparente)
Cifra los archivos de la base. Si alguien los copia, no puede leerlos sin la llave.

      
Keystore
Archivo donde Oracle guarda la llave que usa TDE.

      
Tablespace y datafile
Un tablespace es un espacio lógico donde se guardan tablas; un datafile es el archivo físico que lo contiene.

      
Data Redaction
Oculta el valor de una columna en el resultado de una consulta (por ejemplo, la cédula aparece en blanco), sin cambiar el dato guardado.

      
VPD (base de datos privada virtual)
Filtro automático que hace que cada usuario vea solo las filas que le corresponden.

      
Auditoría unificada
Registro de Oracle de quién hizo qué y cuándo.

      
RMAN
Herramienta de Oracle para hacer respaldos y restaurarlos.

      
ARCHIVELOG
Modo en que Oracle guarda el historial de cambios, lo que permite recuperar la base a un momento exacto.

      
Data Pump
Herramienta de Oracle para exportar datos a archivos.

      
Papelera (recycle bin)
Lugar donde quedan las tablas borradas hasta que alguien las purga; mientras estén ahí, se pueden recuperar.

      
Listener y puertos 1521 / 5500
El listener recibe las conexiones de red a Oracle. El puerto 1521 es la entrada para consultas y el 5500 la consola web.

      
sqlnet.ora
Archivo de configuración de red de Oracle; ahí se activa el cifrado de la comunicación.

      
Línea base
La medición inicial, hecha antes de aplicar las medidas, para compararla después.

      
Evidencia
Archivo con el resultado de una consulta o prueba, con fecha, que demuestra algo sin depender de la palabra de nadie.

      
Nivel de madurez 0-4
Nota de cada medida: 0 no existe, 1 existe por defecto o a medias, 2 está diseñada, 3 funciona y está probada, 4 además se revisa periódicamente.
